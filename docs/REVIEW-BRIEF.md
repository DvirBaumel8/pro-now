# PRO NOW — מסמך פתיחה למתכנת שבא לסקור

נכתב ב־2026-09-28 לבקשת עמית, לפני סקירה של מתכנת חיצוני. המטרה היא
לענות על שתי שאלות: **האם עובדים נכון ומאובטח**, ו**איך אפשר לעבוד ביעילות
רבה יותר ובפחות טוקנים**. כל מה שכתוב כאן נבדק בפועל על המחשב של עמית,
והמספרים נמדדו ולא הוערכו.

---

## 1. מה זה הפרויקט

PRO NOW הוא מרקטפלייס בזמן אמת: לקוח מבקש בעל מקצוע מאומת שיגיע **עכשיו**,
ובעלי מקצוע בוחרים מתי להיות מחוברים ומקבלים קריאות קרובות אליהם.
אין בו לוח הזמנות מראש, אין מכרזים, והמשתמש לא מדפדף בין מקצוענים.

**את כל הקוד כתב Claude Code** (מודל AI), בהנחיה של עמית, שאינו מתכנת.
עמית קובע את המוצר ומאשר, ו־Claude כותב, בודק ומתעד.

### המבנה (monorepo, npm workspaces, TypeScript)

| תיקייה | מה יש בה | מצב |
|---|---|---|
| `apps/api` | Node + Fastify, Prisma, PostgreSQL 16 + PostGIS, Redis | רץ מקומית. migration בסיס קיים ונבדק מול DB אמיתי. **לא פרוס בשום מקום.** |
| `apps/customer-mobile`, `apps/pro-mobile` | React Native + Expo | typecheck נקי. `expo export` לא נמדד על המחשב הזה. **לא הותקנו על מכשיר.** |
| `apps/admin` | Next.js | ה־build ירוק |
| `packages/types` | מודל הדומיין, הקטלוג (47 שירותים), state machines, ממשקי ספקים | הלב של הלוגיקה, עם 726 בדיקות |
| `packages/ui` | רכיבי עיצוב ומסכים משותפים (react-native + react-native-web) | 199 בדיקות |
| `packages/validation`, `api-client`, `config` | zod, client מוקלד, סכמת env | |
| `tools/design-preview` | **הדמו.** Vite + React שמריץ את המסכים של `packages/ui` בדפדפן, ועיר תלת־ממדית (three.js) | זה מה שמוצג למשקיעים |

**מה שמשקיעים רואים** הוא `tools/design-preview`, שמפורסם כ־Artifact ב־claude.ai
(קישור שכל מי שמחזיק אותו יכול לפתוח). הדמו משתמש באותם מסכים שהאפליקציות
משתמשות בהם, אבל **הנתונים בו הם fixtures ולא השרת**. כל שירות עובד
מההתחלה עד הסוף בתוך הדפדפן, ובוט בודק את כל 47 השירותים.

### ספקים ("אין אינטגרציות מזויפות")
תשלומים, KYC, מפות, התראות ומוניטין חיצוני הם **ממשקים עם adapter של sandbox**
(`packages/types`, provider interfaces). ההחלטה איזה ספק לבחור היא של עמית ועדיין
פתוחה (`docs/18-ROADMAP.md §Open Decisions`). שום דבר בקוד לא טוען שהוא
production.

## 3. מה מצאתי: אבטחה וגיבוי

### דחוף
1. **72 commits לא הועלו ל־GitHub.** `master` נמצא 72 commits לפני
   `origin/master`, כלומר עבודה של כמה ימים קיימת **רק על הדיסק של המחשב הזה**.
   אם הדיסק נפגע, היא אבודה. הריפו ב־GitHub פרטי (בקשה אנונימית ל־API
   מחזירה 404), אז אפשר לדחוף בבטחה. **המלצה:** `git push` עכשיו, ואחר כך
   בסוף כל יום עבודה.
2. **אין CI.** אין `.github/workflows`, והבדיקות רצות רק מקומית כש־Claude
   זוכר להריץ אותן. **המלצה:** GitHub Actions שמריץ lint, typecheck ו־test על
   כל push. זו עבודה של כמה דקות.

### חשוב
3. **קבצים בינאריים ב־git:** 1,337 תמונות וקבצי zip. `.git` שוקל 218MB,
   ו־`tools/design-preview/public` שוקל 169MB. כל גרסה של כל ציור נשמרת לתמיד.
   **המלצה:** Git LFS לתמונות, או אחסון חיצוני (bucket) ו־manifest.
4. **הדמו המפורסם פתוח לכל מי שמחזיק את הקישור.** אין בו נתונים אמיתיים או
   סודות, אבל הוא חושף את כל המוצר. זה בסדר למשקיעים, אבל אם צריך יותר
   שליטה, אפשר לשתף עם אנשים מסוימים בלבד.
5. **Artifact מוגבל ל־512 קבצים.** נתקלנו בזה הלילה. הפתרון היה ניקוי קבצים,
   וכשהארט יגדל נצטרך לארוז תמונות (atlas) או לשנות את שיטת האירוח.

### תקין
- `.env` ב־`.gitignore` (נבדק עם `git check-ignore`). אין סודות בקבצים שב־git.
- אין ספקים אמיתיים מחוברים ואין מידע אישי אמיתי.
- השרת סמכותי בכל מה שקשור למצב העבודה, למחיר ולשיבוץ (לפי ה־docs). ה־row lock
  (`SELECT … FOR UPDATE`) נבדק מול Postgres אמיתי (`npm run verify:rowlock`).
- זיהוי תמונה וטקסט בדמו עובר דרך יכולת `sample` של claude.ai, על חשבון הצופה
  ובאישורו, ובוחר רק מתוך רשימת השירותים שלנו.

### לא נבדק, שווה שהסוקר יסתכל
- אבטחת ה־API עצמו: auth, rate limiting, הרשאות לפי תפקיד. קיים קוד ב־`apps/api/src/plugins`.
- מודל הנתונים (`apps/api/prisma/schema.prisma`) ו־`docs/11-SECURITY.md` ו־`12-PRIVACY.md`.
- תלויות: לא הורץ `npm audit`.

## 4. מה מצאתי: טוקנים ויעילות

**איפה הטוקנים הולכים:**
1. **סשנים ארוכים מאוד.** תיקיית ההיסטוריה של Claude לפרויקט שוקלת 775MB
   בשני סשנים בלבד. בסשן אחד ארוך כל תור שולח מחדש הקשר ענק, וגם
   כשהוא ב־cache זה עולה. **המלצה:** סשן חדש לכל משימה, ו־`CLAUDE.md` ו־`docs`
   הם הזיכרון בין סשנים (בשביל זה הם קיימים).
2. **קבצים ענקיים.** `tools/design-preview/src/App.tsx` מכיל 6,576 שורות,
   `city/street.ts` מכיל 4,596 ו־`city/City.tsx` מכיל 3,006. כל פעם שצריך לגעת בהם
   נקראים חלקים גדולים. **המלצה:** לפצל את `App.tsx` לפי מסכים (customer/pro/shell).
3. **הערות ארוכות בקוד.** הסגנון כולל הסברים ארוכים עם ציטוטים של עמית
   בתוך הקוד. זה מתעד את ה"למה", אבל מנפח כל קריאה של קובץ. **המלצה:** את
   הסיפור ל־docs או להודעות commit, ובקוד הערה של שורה או שתיים.
4. **עבודה ויזואלית דרך צילומי מסך.** יצירת ארט ב־ChatGPT דרך הדפדפן ובדיקה
   בצילומי מסך צורכות הרבה. **המלצה:** לייצר תמונות ישירות דרך Images API
   בסקריפט (עולה כסף ב־OpenAI, אבל חוסך הרבה טוקנים של Claude).
5. **מודל לפי משימה.** עבודה מכנית (הכנסת ארט, הרצת בדיקות, צילומים) יכולה
   לרוץ על מודל זול יותר, ואת המודל החזק שומרים לארכיטקטורה ולוגיקה.
6. **`EPIC-0-REPORT.md` באורך 2,448 שורות.** ה־`CLAUDE.md` מפנה לקרוא ממנו כמה
   סעיפים בתחילת כל סשן. **המלצה:** לתמצת למסמך "מצב נוכחי" של עמוד אחד, ואת
   ההיסטוריה להעביר לארכיון.

