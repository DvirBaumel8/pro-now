  signed in.** Done: e2e, by email link and by Google.
- **Installable.** Chrome's `Page.getInstallabilityErrors` returns `[]`,

- **Loading, error and offline states** come from the query status (the

Totals: 15 e2e tests (×2 engines, minus one Chromium-only), 55 API
integration tests, full CI green on GitHub (three jobs).

## Security review note

- Session: Better Auth's httpOnly cookie on one origin. The app never sees
  a token; the client sends `credentials: "include"` and nothing else.
- The route guards in the app only pick a screen. Every rule is enforced
  again by the API (W1's access layer).
- `PATCH /api/v1/me/customer` is CUSTOMER-only, with a strict body (an
  unknown field is a 400) and the avatar checked against `AVATARS`.
- The service worker never caches `/api`, and its navigation fallback
  excludes `/api`.
- Static serving never answers `/api/*` with the app, and a missing file
  is a 404, not the app.

## Found along the way

- **I broke the demo's build** (`d4c7e0d`, a workspace-wide
  react-native-svg upgrade). It went unnoticed because CI didn't build the
  demo. Fixed in `0388783`; CI now builds both front ends.
- Vite re-bundling a first-seen dependency mid-session briefly loaded two
  Reacts ("Invalid hook call", dev only). The app's dependencies are now
  pre-bundled.
- The demo is deliberately `dir="ltr"` (its rows use `row-reverse`), so
  the product is too. The plan's `dir="rtl"` would have mirrored every
  row.
